# Hasil uji coba nyata (pasien uji, 16 Nov 2026, klinik trial)
Urutan & waktu nyata:
1. Pasien baru (form pendaftaran → SIMPAN DATA PASIEN): POST master/pasien/create 202 ms (+ save-base64 ttd + PUT auth/user). No RM otomatis.
2. Data Pasien → cari → tombol hijau "send" (ikon ▶) → dialog "PROSES PELAYANAN : <nama> (<umur>)": tombol besar per poli (POLI UMUM, POLI GIGI, POLI GIGI BPJS, LABOLATORIUM, POLI KIA, POLI UMUM 2) → muncul "Pilih dokter" & "Pilih penjamin" (wajib) + Prioritas, Indikator Pasien, Sebutkan Penyakit, toggle INTEGRASI SATUSEHAT / INTEGRASI BPJS, tombol PROSES PERAWAT / PROSES POLI. PROSES POLI → POST master/kunjungan 356 ms → notifikasi "… Berhasil di proses… Nomor antrean : PU001".
   (Memilih dokter yang belum terintegrasi SatuSehat memunculkan peringatan merah "Maaf dokter ini belum terintegrasi dengan satusehat.." — tidak memblokir.)
3. POLI DOKTER (antrean): kolom No, Prioritas, Indikator, Tanggal, No Antrean, Nama, Umur, Keluhan, Poli, Penjamin, Status, Tindakan. Tombol per baris: PELAYANAN (hijau) dan PILIH ▼ (Panggil, Proses, Farmasi, Selesai, Cetak Billing, Detail Kunjungan, Batalkan, Hapus Kunjungan Pasien).
   PELAYANAN → PUT master/antrian/{id} status 203 (253 ms) → buka /proses/Diagnosa/<b64>.
   ⚠ Setelah pindah pasien, beberapa request awal masih memakai id_kunjungan pasien SEBELUMNYA (store lama). Store `pelayanan.pasien` baru benar setelah GET master/kunjungan (~0,5 dtk). Otomasi WAJIB menunggu `store.pasien.id_kunjungan === atob(url terakhir)`.
   ⚠ Komponen lama tetap memanggil GET diagnosa/<id lama> setelah SUBMIT (listener bocor) — abaikan, tapi jangan andalkan data komponen dari halaman sebelumnya.
4. Isi anamnesa/TTV lewat store (`Object.assign(store.state.pelayanan.pasien,{keluhan,…})`) → UI langsung terisi (reaktif). IMT TIDAK dihitung otomatis bila diisi lewat store (countIMT hanya saat input) → hitung sendiri imt = BB/(TB/100)^2.
5. Diagnosa via UI: ketik "J06.9" di "Diagnosa Utama" → 1 opsi "J06.9 - Acute upper respiratory infection, unspecified" → klik → kolom Kasus terisi otomatis, TACC menjadi null (bukan "-1"). Klik SIMPAN (di kanan "DIAGNOSA TAMBAHAN") → POST master/kunjungan/diagnosa **13,5 detik** (lambat!) → "Diagnosa berhasil di simpan". Tombol berputar selama itu; jangan klik ulang.
6. Resep obat satuan via UI: ketik nama → opsi "NAMA (stok)" → klik → Kode Batch otomatis (stok>0) → Jumlah → Signa (ketik "3 x 1", pilih dari daftar) → SIMPAN (hotkey Ctrl+S; TAMBAH OBAT = Ctrl+F1) → POST master/kunjungan/resep 1,55 dtk → "Resep berhasil di simpan". Stok langsung berkurang (58→48).
   ⚠ Tabel "Daftar Resep" & store.pasien.resep TIDAK langsung diperbarui setelah simpan (tetap TOTAL 0) sampai SUBMIT/reload. Verifikasi pakai POST master/kunjungan/get-resep.
7. Racikan via dialog "Tambah Racikan": Nama Racikan* (form.racikan_nama), Jenis Racikan* (form.racikan_jenis, opsi Kertas Puyer/Plastik Puyer/Kapsul/Botol Sirup/Pot Salep/Tube Salep/Botol Tetes/Sachet), Jumlah Racikan* (form.racikan_qty), Signa Racikan* (teks bebas, form.racikan_signa), baris obat (Nama Obat, Kode Batch, Jumlah, Diskon) + TAMBAH OBAT, SIMPAN → POST master/kunjungan/racikan 3,3 dtk + POST racikan-kunjungan/add 135 ms → "Berhasil menambahkan data racikan". Kartu racikan tampil: "Jenis: Kertas Puyer • Jumlah Racikan: 10 • Signa: 3 x 1", "2 obat", harga.
8. SUBMIT (tombol biru kanan atas) → PUT master/kunjungan/{id} 273 ms → "Data berhasil di update..." → GET master/kunjungan (store diperbarui; resep/racikan/icdx muncul). Pada pasien non-BPJS tidak ada kiriman PCare.
9. Tindakan via UI: "Jenis Tindakan" (QSelect, option-label tarif_nm, option-value tarif_id, emit-value) ketik "Konsul" → opsi Konsultasi, Konsultasi lanjutan, Konsultasi Dokter Umum, … → pilih → Harga terisi ("Rp 0" di trial, string berformat) → SIMPAN → POST master/kunjungan/tindakan **30,6 detik** (sangat lambat!) body {tindakan:[{no,val:"T24522294170",diskon_tindakan,jumlah_tindakan,asisten_tindakan,keterangan_tindakan,harga_tindakan:"Rp 0"}],id_kunjungan} → "1 Tindakan berhasil disimpan" → GET master/kunjungan.
   ⚠ Simpan Tindakan & Diagnosa bisa 13–30 dtk. Otomasi harus menunggu (tombol loading) dan tidak klik ulang; batas tunggu ≥ 60 dtk.
